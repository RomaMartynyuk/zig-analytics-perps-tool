The three new adapters make one, two and four public bulk requests respectively. They use the existing 75-minute warm-instance cache and retry/backoff helper. Each requires complete per-market coverage for a metric; if any eligible market lacks that field, that metric becomes `NULL` while other metrics can still be saved. No private keys or authenticated trading APIs are used.

Bullet and N1 publish quote-volume numbers directly in their public live responses. Their open-interest numbers are base asset units; multiplying each market by its own mark price produces the USD notional before summation. Perpl publishes scaled integers; its collateral token currently is AUSD (six decimals). The volume value is therefore AUSD nominal, treated as USD-equivalent as in the exchange's quoted market interface. This carries AUSD peg risk and must be disclosed when comparing exact USD values. Perpl's `state.tvl` is not mapped to Zig TVL because its market-level meaning has not been established as independent protocol deposits.

The canonical registry remains `src/data/projects.json`. Bullet and Perpl are added as active independent venues. The existing N1 registry entry is now backed by verified mainnet data. TrueNorth and Tread.fi remain visible as projects but are inactive in the venue snapshot/aggregate universe; old rows remain in Neon. Entropy and Bullpen are excluded from the registry so Hyperliquid activity is not counted twice. If Zig later stores a HIP-3 child or specialized venue as its own researchable protocol, explicit per-metric aggregate eligibility must be added to the historical schema and analytics queries before activation.

No database migration is required for the three independent venues: the collector syncs them by stable slug and persists actual daily values on its next UTC run. TVL remains `NULL` unless a reliable DeFiLlama protocol mapping returns a real value. Funding and external historical backfill are outside this release.
